## Project Overview

**XMarkdownNetlifyDemo** is an Elm-based web application for viewing and editing XMarkdown documents. It's a single-page browser application deployed to Netlify that renders extended markdown syntax with support for images, lists, quotations, and custom formatting.

### Key Libraries & Dependencies
- **xmarkdown-compiler** (jxxcarlson/xmarkdown-compiler): Core markdown parsing and compilation
- **elm-ui** (mdgriffith/elm-ui): UI framework for layout and styling
- **elm-visualization**: Charting and visualization utilities
- **elm-geometry & elm-units**: Mathematical primitives for geometric calculations
- **elm-syntax-highlight**: Syntax highlighting for code blocks
- **elm-csv**: CSV parsing

## Development Setup

### Installation & Build Commands

```bash
# Install dependencies
npm install

# Development server with hot reload (port 8000)
npm run dev

# Production build (compiles Elm to main.js)
npm run build

# Build script (automated)
./build.sh
```

### Development Workflow

1. **Starting development**: Run `npm run dev` which uses `elm-live` for live reloading
2. **Production build**: Run `npm run build` which compiles `src/Main.elm` to `main.js`
3. **Netlify deployment**: Automatically runs build command on deploy (configured in netlify.toml)

## Architecture

### Module Structure
- **Main.elm**: Entry point using Browser.element; manages application state, file I/O, window resizing, and live reload sync
- **Ports.elm**: Port definitions for JavaScript interop (highlight styling, editor theme sync)
- **Data/XMarkdown.elm**: Sample markdown data for demo content

### Key Patterns

**Elm Architecture (TEA Pattern)**:
- **Model**: `{ sourceText, initialText, windowWidth, windowHeight, theme, fileName, lrSyncMatches, ... }`
- **Update**: Handles messages like `InputText`, `Render`, `FileSelected`, `LRSync` (live reload sync)
- **View**: Renders via HTML and elm-ui elements
- **Subscriptions**: Window resize events and live reload sync from Ports

**Port Communication**:
- `lrSyncRequest`: Incoming subscription for live reload sync requests from JavaScript
- `injectHighlightCSS`: Outgoing command to inject syntax highlighting styles
- `setEditorHighlightColor`: Outgoing command to update highlight theme color

**File Handling**:
- Uses `File.Select` for opening markdown files
- Uses `File.Download` for saving documents
- Maintains `fileName` in model state

### External Integrations

**XMarkdown.API** (`xmarkdown-compiler` library):
- `fromMsg`: Converts MarkupMsg to rendering commands
- `defaultCompilerParameters`: Theme and rendering configuration
- `BlockMatch`: Data structure for live reload sync matching

## File Structure

```
├── src/
│   ├── Main.elm              # Application entry point, TEA pattern
│   ├── Ports.elm             # JavaScript port definitions
│   └── Data/XMarkdown.elm    # Demo markdown content
├── index.html                # HTML template (human-editable, loads main.js)
├── main.js                   # Compiled Elm application (generated by elm make)
├── elm.json                  # Elm dependencies and project config
├── package.json              # npm dependencies and scripts
├── netlify.toml              # Netlify deployment config
└── build.sh                  # Build automation script
```

**Important Notes**:
- `main.js` is generated by `elm make` and regenerated on every build — do not edit directly
- `index.html` is a human-editable template that loads `main.js` and initializes Elm with flags — this will NOT be overwritten by the build process
- Keep the `<script src="main.js"></script>` tag in index.html for the build to work

## Derivation from Source Projects

This project was derived from [DemoTOCMd](../xmarkdown/DemoTOCMd/), which uses elm-watch. Key differences in this version:

- **Build tool**: Uses `elm make` + `elm-live` instead of elm-watch
- **HTML template**: Uses a single `index.html` template in root (not `assets/index.html`)
- **Output**: `main.js` in root (not `assets/main.js`)

The `index.html` template must always contain proper Elm initialization with flags:
```javascript
var app = Elm.Main.init({
    node: document.getElementById("elm"),
    flags: {
        window: {
            windowWidth: window.innerWidth,
            windowHeight: window.innerHeight
        }
    }
});
```

If you ever need to re-derive `index.html` from a source project, use this as the template structure.

## Deployment

The app deploys to Netlify. Build command is configured in `netlify.toml`:
```toml
[build]
command = "npm run build"
publish = "."
```

Root directory is published (contains index.html and main.js). Ensure `npm run build` succeeds before pushing.

## Common Development Tasks

### Adding a New Elm Module
1. Create file in `src/` (e.g., `src/Utils/Parser.elm`)
2. Add to `elm.json` source-directories if needed (currently just `src`)
3. Import in Main.elm and wire into update/view as needed

### Updating Dependencies
1. Edit `elm.json` version constraints
2. Run `npm install` (triggers elm package resolution)
3. Note: Elm compiler handles dependency locking via elm-stuff/

### Debugging Live Reload Sync
- Check `lrSyncMatches` in model (populated from `LRSync` message)
- Verify Ports.lrSyncRequest subscription is active in subscriptions
- JavaScript live reload server sends sync requests to trigger re-render

### Theming
- Theme is managed in model as `Light | Dark` (from XMarkdown.Types)
- `setEditorHighlightColor` port sends theme color to JS
- Syntax highlighting CSS injected via `injectHighlightCSS` port
